# Fixi - מערכת מעקב עלויות ומכרזים למטבח

מערכת לניהול עצי מוצר (BOM), מעקב מלאי וזיהוי פריטים שדורשים יציאה למכרז, עבור
תפריט של 3 מנות: **המבורגר**, **סלט קיסר**, **קריספי ציקן**.

כל מוצר הוא עץ דינמי שמתרחב בזמן הזמנה לפי מצב השירות:

| מצב | מה נוסף לעץ המוצר |
|-----|-------------------|
| `SIT` (ישיבה במקום) | מפיות בלבד |
| `TA` (Take Away) | שקית, סכו"ם חד-פעמי, מפיות + אריזה ייעודית למנה (קופסת המבורגר/קופסת סלט עם מכסה) |

## מבנה הקוד

| קובץ | תפקיד |
|------|-------|
| `database.py` | סכמה של SQLite + חיבור |
| `seed.py` | טעינת קטלוג: רכיבים, מוצרים, רצפטים, תוספות לפי מצב שירות, אריזות TA לכל מוצר |
| `services.py` | לוגיקה עסקית: `product_tree`, `record_order`, `inventory_status`, `tender_candidates` |
| `app.py` | Flask - לוח בקרה, דף מוצר, הזמנה, מלאי, מכרזים |
| `simulate_year.py` | סימולציית 365 ימים עם עונתיות + דוחות מפורטים |

## הרצה

```bash
pip install -r requirements.txt
python seed.py           # טעינה ראשונית של הקטלוג
python app.py            # http://127.0.0.1:5000
```

## סימולציית שנה מלאה

```bash
python simulate_year.py
```

הסקריפט מייצר:

1. **BOM מפורט לכל מנה** - SIT מול TA, עם מקור כל רכיב (recipe / service_extra / ta_packaging),
   כמות, יחידה ועלות.
2. **מחזור מכירות חודשי** - מספר מנות לכל מוצר, פיצול TA/SIT, סה"כ לחודש.
3. **שימוש חודשי ברכיבים** - מטריצה של כל הרכיבים × כל החודשים.
4. **פרמטרים מוצעים להזמנה אוטומטית** - Reorder point + Order quantity לכל רכיב,
   על בסיס צריכה נצפית + זמן אספקה + מלאי ביטחון של 30%.
5. **`simulation_output.json`** - כל הנתונים בפורמט מכונה להזנת מערכת ההזמנות.

### הנחות הסימולציה (ניתן לכיוון ב-`simulate_year.py`)

- ביקוש יומי בסיסי: המבורגר 40, קריספי ציקן 28, סלט קיסר 18
- סופי שבוע (שישי-שבת) +35%, ראשון -15%
- קיץ +20%, חורף -10%, חגים (אפריל/ספטמבר) +5%
- יחס TA/SIT: בחול 45/55, בסופ"ש 30/70
- רעש יומי אקראי של ±10%
